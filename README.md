# ادرس معي — النسخة النهائية: مفتاح API بمتغيرات بيئة Vercel فقط

## ما تغيّر

- **ما فيه ولا لوحة أدمن، ولا رابط تحطه بالتطبيق، ولا أي إعداد تقني بالواجهة إطلاقًا.**
- المفتاح (`GEMINI_API_KEY`) واسما النماذج (`GEMINI_TEXT_MODEL`, `GEMINI_TTS_MODEL`) صاروا **متغيرات بيئة على Vercel نفسه**، يقرأهم فقط كود بمجلد `api/` يشتغل على السيرفر — الكود يلي بالمتصفح (كل ملفات `js/`) ما فيه ولا أي أثر إلهم، ولا حتى اسم متغير.
- التطبيق والـ API صاروا **مشروع Vercel وحد** (بدل موقع + Worker منفصل بالنسخة اللي قبل). أبسط بكثير: نشر مرة وحدة، بدون CORS، بدون رابط تربطه يدويًا.

## البنية

```
adris-maai/
├── index.html / sources.html / chat.html / studio.html   الواجهة
├── css/, js/, assets/                                      نفس السابق
└── api/                    ← جديد: دوال Vercel (Edge Functions)
    ├── upload-start.js      يبدأ رفع الملف (يستخدم GEMINI_API_KEY)
    ├── file-status.js       يتحقق من حالة الملف بعد الرفع
    ├── chat.js               المحادثة/التلخيص/السلايدات (streaming)
    └── tts.js                 توليد الصوت (بودكاست + سلايدات)
```
لاحظ: ملفات `api/*.js` ما تترفع لأي استضافة ثابتة عادية (Netlify Static/GitHub Pages) — هاي خاصة بـ Vercel حصرًا لأنه هو يلي يحوّلها تلقائيًا لدوال سيرفر تشتغل خلف الكواليس.

## النشر على Vercel — خطوة بخطوة

### 1. ارفع المجلد لمشروع Vercel
إما اسحب المجلد كامل (`adris-maai/` بكل شي جواه، بما فيه `api/`) على [vercel.com/new](https://vercel.com/new)، أو اربطه من GitHub. Vercel يتعرف تلقائيًا إن `api/` دوال سيرفر — ما تحتاج أي إعداد build يدوي.

### 2. ضيف متغيرات البيئة — بالضبط هاي الأسماء
من لوحة المشروع بـ Vercel: **Settings → Environment Variables**، وضيف:

| الاسم بالضبط | القيمة | ملاحظة |
|---|---|---|
| `GEMINI_API_KEY` | مفتاحك من Google AI Studio (يبدأ `AIzaSy...`) | فعّل "Sensitive" إذا الخيار موجود، عشان ما تنعرض القيمة لاحقًا حتى لك |
| `GEMINI_TEXT_MODEL` | `gemini-3.6-flash` | اختياري — إذا ما ضفته، الكود يستخدم هذي القيمة افتراضيًا أصلًا |
| `GEMINI_TTS_MODEL` | `gemini-3.1-flash-tts-preview` | اختياري — نفس الشي |

اختر **Production** (و **Preview**/**Development** إذا بدك تجرب قبل ما تنشر) لكل متغير.

### 3. أعد النشر (Redeploy)
أي متغير بيئة تضيفه ما يشتغل على نسخة منشورة مسبقًا — لازم **Redeploy** من تبويب Deployments بعد ما تضيف المتغيرات (زر "Redeploy" بس، بدون ما تغيّر كود).

خلص. افتح رابط موقعك — يشتغل مباشرة بدون أي خطوة ثانية من طرفك ولا من طرف أي زائر.

## ليش صار أبسط وأأمن مع بعض

- **الأمان الحقيقي**: المفتاح موجود بس على سيرفرات Vercel، ما يوصل المتصفح إطلاقًا — حتى لو حدا فتح أدوات المطوّر وفحص كل طلب، ما رح يشوف المفتاح.
- **رفع الملفات الكبيرة لسا يشتغل بدون حدود**: خطوة "بدء الرفع" (طلب صغير) تمر عبر `api/upload-start.js`، لكن رفع بايتات الملف الفعلي (مهما كان حجمه) يروح مباشرة من متصفح المستخدم لرابط جلسة مؤقت ترجعه Google — ما يمر عبر Vercel إطلاقًا، فما فيه أي قيد حجم.
- **صفر إعداد للمستخدم**: ما في "أدمن" ولا "رابط سيرفر" تحطه — بمجرد ما تضيف المتغيرات الثلاثة وتعمل Redeploy، كل شي جاهز لكل الزوار تلقائيًا.

## توليد الصور — هل مجاني؟

لا، مو مجاني (لو ضفته مستقبلًا). حسب أسعار Google الحالية:

| الموديل | السعر التقريبي لكل صورة |
|---|---|
| Imagen 4 Fast | ~$0.02 |
| Gemini 2.5 Flash Image | ~$0.039 |
| Gemini 3.1 Flash Image | ~$0.045–$0.15 (حسب الدقة) |
| Gemini 3 Pro Image | ~$0.13 (2K) إلى $0.24 (4K) |

لو ضفتها مستقبلًا لموقع فيه زوار كثار، التكلفة تتراكم مع كل صورة — يفضّل تحط حد استخدام يومي بـ `api/` قبل ما تفتحها للعامة.

## بقية الملاحظات (لسا صحيحة)
- شرح بالسلايدات (4-12 شريحة، صوت مستقل لكل شريحة) والنظرة الصوتية (بودكاست بمتحدثين) لسا تجريبيين وصوتهم مؤقت بالجلسة (يضيع بالـ refresh) — تخزين دائم فكرة زينة لمرحلة الاشتراك المميز لاحقًا.
- التصميم mobile-first بأربع صفحات منفصلة مع تنقل شريط سفلي على الهاتف وتبويبات فوق على الكمبيوتر.
